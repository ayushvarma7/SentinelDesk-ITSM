SentinelDesk

Multilingual incident triage with precedent-grounded drafting. A ticket arrives, gets classified, matched against resolved history, and either answered with citations or stopped at a gate that can explain itself.

28,587 tickets · EN/DE · 22,863 KB rows · 5,718 holdout · seed 42

Architecture

One encoder pass does three jobs. The 384-dimension vector it produces is the classifier's feature, the retrieval query, and — when the KB was built — the index itself. There is no second model to load and no duplicated compute.

The ML side

Four logistic-regression heads over [word TF-IDF ‖ e5 embedding], C=32, class_weight="balanced". Every setting was chosen on a 10% KB validation slice; the holdout was evaluated once, on the frozen model.

Queue sits at 0.61 because it has ten classes at 21× imbalance and the labels genuinely overlap — Technical Support, Product Support and IT Support are not cleanly separable. Priority sits at 0.62 for a different reason: it is close to unlearnable from this text. High-priority share by type is 40.2 / 42.8 / 39.4 / 33.5 percent across Change, Incident, Problem and Request. Nearly flat. The strongest keyword signal, outage/down, moves it only from 37.6% to 62.9%.

Priority's ECE is the worst of the four, and that is deliberate. Anything with P(high) ≥ 0.25 is labelled high, so those tickets carry confidences between 0.25 and 0.5. The threshold trades about three points of macro-F1 for about thirteen points of high-priority recall. A missed outage costs more than a false alarm.

Why not a fine-tuned transformer. About 20 ms per ticket on CPU, calibrated probabilities the gate can threshold, and minutes to train. The label noise caps any model on queue and priority, so the ceiling a transformer would reach for is not there to reach.

Retrieval and the two stores

Exact cosine search in numpy over L2-normalised vectors — not faiss. On macOS, faiss and torch each bundle libomp, and importing faiss before torch aborts the process with OMP: Error #15. The pipeline imports torch. At 22,863 × 384 an exact matmul is about 0.9 ms, so there was nothing to gain.

That constraint turned out to be a gift. A plain matrix grows by np.vstack; a built faiss index would need rebuilding. Appending a precedent costs one encode, about 11 ms.

Keeping them apart is about blast radius more than correctness. A source column on one index would give the same reproducibility guarantee. But the frozen index costs five minutes of GPU time to rebuild and three people's work depends on it, while the live file starts at zero bytes and clear_live() is two unlinks. A bug in the append path can only damage the disposable one.

Cross-lingual retrieval does not happen on its own. An early measurement put it at 16.3% of top-5 hits, which was wrong — it counted the dataset's language label, and about 15% of labels disagree with the text. Measured against detected language it is 2.8% for German queries and 3.1% for English. e5 strongly prefers same-language neighbours.

It surfaced because a task failed: hunting for a German demo ticket whose top-5 contained an English precedent found nothing, because there was nothing to find. The fix reserves one slot in the top-5 and runs a second search restricted to the other language — a reserved slot alone was not enough, since the unrestricted top-30 for a German query is thirty German tickets.

Grounded drafting

Three layers, in increasing order of trust. The prompt asks for grounded JSON. Code then verifies what comes back. If there is no key or the call fails, an extractive fallback quotes the closest same-language precedent.

  • Citation check — every cited id must be in the retrieved set. An id in the prose but missing from the model's own list still counts; an id in neither is a fabrication.
  • Figure guard — any number carrying a currency symbol, a percent sign or a time unit that appears in no precedent is flagged. Only 0.3% of KB answers contain such a figure, so this almost never false-positives.
  • Scrub — 48% of KB answers carry anonymisation tokens. They come in two shapes: 10,956 answers use <tel_num>-style tokens and 2,696 use [Name]-style ones. A scrub that handled only the first shape would have left roughly 12% of answers leaking.

The scrub/PII collision. PII masking rewrites real data into <email> and <tel_num> before the ticket reaches the model. Scrub was deleting exactly those shapes from the reply, so an echoed token produced "we updated the details for and will call once account is verified." Masked-PII tokens now become readable phrases in the reply's own language; dataset noise is still removed. Neither layer could see this alone.

Language is scored against the text, not the label. Against the label it reads 0.33, and every miss is a ticket labelled de whose body is written in English. The detector is right and the dataset is wrong — the same 12% disagreement the EDA found.

The escalation gate

Deterministic rules, no model in the decision path. Each rule returns a sentence with its own numbers in it, so a badge explains itself without anyone opening the source: "No sufficiently similar precedent (best match 0.8586 < 0.8650)".

The rule that carries safety is not a confidence floor. It is P(high) × P(Incident or Problem) ≥ 0.20 — the probability of the dangerous class, which fires even when the argmax labels are wrong. Incident and Problem both mean "service is broken" and the classifier confuses them, so both count.

Why confidence floors could not do this job. The hard rule needs both labels right and misses about 23% of true high-priority Incidents. Recovering that with confidence floors meant escalating ~70% of all traffic and 93% of hand-typed benign tickets. Keying on the dangerous class gets the same safety at 42% escalation and 14% benign loss.

The calibration frontier

A sweep of 100 threshold settings against two distributions at once — the 2,286-ticket validation slice where labels exist, and 22 hand-written tickets where they do not. Leakage discipline

Structural rather than remembered. prepare_data.py writes the holdout as two files: test_inputs.parquet with only ticket_id, subject and body, and test_labels.parquet with everything else. The inference path cannot read a label because the columns are not in the frame it loads.

Test tickets are embedded on every evaluation — encoded, searched with, discarded. Embedding is a read; indexing is the write that never happens. The index holds exactly the 22,863 KB rows, with zero holdout ids inside it.

Decisions worth defending

  • One encoder, three jobs. Classifier features, retrieval queries and the index all come from the same pass. Cross-lingual capability comes free with a multilingual encoder; so does a language head trained on the data already present.
  • numpy over faiss. Forced by a macOS libomp conflict, vindicated by making the live store cheap to append.
  • Verification in code, not in the prompt. The prompt is a request; the citation and figure checks are guarantees. A model that ignores an instruction still cannot smuggle a fabricated id past a set membership test.
  • No draft at all when escalating. Showing a suggested reply beside "escalate to on-call" invites someone to send it.
  • Only human resolutions become precedents. resolved_by is required and recorded. If an AI draft could become a precedent, the next draft would be grounded in the previous guess.
  • Thresholds calibrated on hand-typed text. Holdout percentiles would have escalated 100% of what a person types, because the dataset is synthetic and its tickets sit unusually close to the KB.

Known limits

Hand-typed benign tickets auto-draft at 2 of 14. The generator is not the problem — it scores 1.00 on citations and 0.00 on every failure mode. The gate does not let it run. Cause breakdown for the twelve blocked:

A correction to an earlier version of this page. It attributed part of this to the KB lacking coverage and the model refusing to ground an answer. The measurement does not show that — zero of the twelve are grounding refusals. All are threshold decisions.

Three clearly in-domain tickets: password reset (top-1 0.909, drafts fine); invoice charged twice (top-1 0.879, precedent reads "we will investigate the duplicate charge issue and process the necessary refund", yet escalates as a high-priority Problem); adding a new user (top-1 0.847, blocked by queue 0.40 < 0.50). The precedents are there and they answer the question.

CRITICAL_TYPES includes Problem, added because the classifier confuses it with Incident. Reasonable alone, but the hard rule now escalates 34.2% of all holdout tickets before any other rule fires.

Running it

Python 3.12 — torch publishes no 3.14 wheels, and the first version of this repo was built on 3.14.

pyenv local 3.12.8 && python -m venv .venv
.venv/bin/pip install -r requirements.txt
python scripts/prepare_data.py
PYTHONPATH=src python scripts/build_kb_index.py      # ~5 min, M4 GPU
PYTHONPATH=src python scripts/train_classifier.py    # ~96 s
PYTHONPATH=src python scripts/evaluate.py            # holdout, once
./run.sh app                                         # API :8000, admin :5173, customer site :5174

Retrain locally rather than copying heads.joblib — joblib pickles are not safe across scikit-learn versions.
